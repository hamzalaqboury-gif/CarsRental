1What Is This Project?

CarsRental is a complete, production-ready car rental management platform. Think of it as a mini version of Hertz or Enterprise Rent-A-Car — built entirely from scratch with modern web technologies.

In simple words: Customers visit the website, browse available cars, pick dates, book a car, and pay online. Staff (admins and managers) manage the cars, approve bookings, and monitor business performance — all from the same system.

The system handles the full rental cycle: user registration and login, vehicle catalog with filtering, availability checking, reservation creation, payment processing, and dashboard analytics. There is even a built-in chatbot for customer support.

2Main Idea & Goal

🎯 Goal: "Build a platform where customers can rent cars online, and rental staff can manage the entire operation — vehicles, bookings, payments, and users — all in one place."

5How It Works — Step by Step

  • App Loads in Browser
    React starts. AuthContext reads localStorage for a saved JWT token. If a token exists, it calls GET /api/auth/me to verify it's still valid. If not logged in → the user is redirected to /login.
  • User Logs In
    Login.jsx collects email + password. authService.login() sends POST /api/auth/login to Laravel. Laravel validates credentials, signs a JWT token, and returns it with the user object. The token is saved to localStorage and the user is redirected to their dashboard.
  • Client Browses Vehicles
    client/Vehicles.jsx calls vehicleService.list() → GET /api/vehicles. Supports live filters: category, brand, transmission, fuel type, price range, and date range. The backend checks for date conflicts with existing reservations automatically.
  • Client Books a Car
    A booking modal opens. The client picks start and end dates. As they type, reservationService.checkAvailability() fires automatically and shows "Available ✓" or "Not Available ✗". On confirm, POST /api/reservations creates the booking with status pending.
  • Admin Confirms the Reservation
    The admin sees a pending reservation on their panel and clicks Confirm. PATCH /api/reservations/{id}/confirm updates the status to confirmed. An activity log entry is created for the audit trail.
  • Client Pays
    The client opens their reservation and clicks Pay. They choose PayPal or mock payment. PayPal redirects to PayPal's site for approval, then returns to the app. The backend captures the payment and marks the reservation as paid.
  • Analytics Updated
    The admin dashboard (GET /api/admin/dashboard) aggregates totals: revenue, active reservations, total vehicles, new users this month — displayed as stat cards with charts.

7The 4 User Roles

Every user has a role assigned in the database. Each role unlocks different routes, pages, and capabilities.

👑 Super Admin
  • Full system access
  • Manage all users (create, edit, delete)
  • Access all admin dashboards
  • Override any reservation or payment
  • View complete activity logs
🛡️ Admin
  • Manage vehicles (add, edit, delete)
  • Manage all reservations
  • View user list (no delete)
  • Access analytics dashboard
  • Confirm and cancel bookings
📋 Manager
  • Manage vehicles only
  • Confirm / cancel reservations
  • View manager dashboard
  • Cannot manage users
🙋 Client
  • Browse all available vehicles
  • Create reservations
  • Pay via PayPal or mock
  • View own bookings only
  • Update personal profile

8Important Functions & Components

AuthContext — Global Authentication Brain

Every component in the app can access who is logged in via one hook:

const { user, login, logout, isAdmin, hasRole } = useAuth();

// Check if current user is admin/manager
if (isAdmin()) { /* show admin controls */ }

// Check specific role
if (hasRole('super_admin')) { /* super admin only */ }

API Service Layer — Keeping HTTP Clean

All API calls go through service files. Controllers never use Axios directly — they call a service function:

// services/vehicleService.js
const vehicleService = {
  list:   (params) => api.get('/vehicles', { params }),
  get:    (id)     => api.get(`/vehicles/${id}`),
  create: (data)   => api.post('/vehicles', data),
  update: (id, data) => api.put(`/vehicles/${id}`, data),
  delete: (id)     => api.delete(`/vehicles/${id}`),
};

Real-Time Availability Check

In the booking modal, as soon as a client picks dates, availability is checked automatically:

// Fires every time startDate or endDate changes
useEffect(() => {
  if (startDate && endDate) checkAvail();
}, [startDate, endDate]);

const days = calcDays(startDate, endDate);     // e.g. 5 days
const total = days * vehicle.daily_rate;        // e.g. $250.00

ApiResponse Trait (Backend)

Every API response shares the same JSON structure — the frontend always knows what to expect:

// Success response
{ "success": true,  "message": "Vehicles retrieved.", "data": [...] }

// Error response
{ "success": false, "message": "Unauthorized.",        "data": null  }

Role Middleware (Backend)

Routes are protected at the Laravel routing layer — the wrong role can never reach the controller:

// Only super_admin and admin can access these routes
Route::middleware(['jwt.auth', 'role:super_admin,admin'])->group(function() {
    Route::get('/admin/users', [UserController::class, 'index']);
    Route::delete('/admin/users/{id}', [UserController::class, 'destroy']);
});

Reservation Model — Business Logic

The Reservation Eloquent model includes scopes and helper methods that keep query code clean:

// Query scopes — filter reservations by status
Reservation::pending()->get();    // WHERE status = 'pending'
Reservation::confirmed()->get();  // WHERE status = 'confirmed'
Reservation::active()->get();     // WHERE status IN ('pending','confirmed')

// Status check methods
$reservation->isPending();    // true / false
$reservation->isCancelled(); // true / false
$reservation->isPaid();       // true / false

10Conclusion

CarsRental is a well-architected, production-grade web application that demonstrates how a modern full-stack project is built from scratch. It covers the entire car rental lifecycle — from a customer browsing cars on a beautiful glassmorphism UI, to an admin confirming bookings and monitoring revenue on their dashboard.

What makes this project stand out:
✅ Clean architecture (thin controllers, fat services, repository abstraction)
✅ Secure by design (JWT + role middleware on every sensitive route)
✅ Real payment integration (PayPal) with a fallback mock option
✅ Modern UI (React 19, Tailwind, glassmorphism, dark mode, responsive)
✅ Full audit trail (ActivityLog tracks every reservation action)
✅ Role isolation (4 roles, each with their own views and permissions)
✅ Developer-friendly (Docker/Sail, ESLint, Zod validation, form hooks)
